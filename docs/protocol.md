# power-hub 串口协议规范 v2.1（二进制帧）

> 固件与上位机的共同契约。本文档是协议的唯一权威来源；任何改动必须先改这里。
> 本版为二进制帧协议，取代原文本行协议（v1 文档，见 [ADR-0005](./adr/0005-二进制帧协议.md)）。
> 握手应答中的协议版本字节（`proto`）恒为 `0x01`，指二进制协议自身的版本。
> **v2.1 变更（2026-10-14 实机联调修正）**：0x01 通道数据改为 0 基通道索引（ADR-0006）；0x00 兼作状态查询；新增验收矩阵附录。见文末变更记录。

## 1. 物理层

- UART：115200 bps，8 数据位，无校验，1 停止位（8N1）

## 2. 方向模型

严格一问一答（主从式）：

- 所有通信由上位机发起
- hub 收到一条合法命令后应答一帧
- hub **永不主动发送**任何数据（无上电提示、无周期上报）
- hub 上电后处于待命状态，7 通道默认全部开启

## 3. 帧格式

定长二进制帧，无校验字段：

| 方向         | 帧长   | 结构                                      |
| ------------ | ------ | ----------------------------------------- |
| 上位机 → hub | 4 字节 | `0xA5` + 指令(1B) + 数据(1B) + `0x5A`     |
| hub → 上位机 | 7 字节 | `0xA5` + 指令(1B) + 数据(4B) + `0x5A`     |

- 多字节整数一律**小端**（STM32 / x86 原生字节序）
- 帧完整性仅靠"包头 + 包尾 + 定长 + 指令白名单"过滤，不加校验和；将来若需加校验属破坏性升级，经握手 `proto` 字节升版本
- 两端均按定长解析：字节流中定位到 `0xA5` 后读取定长字节，校验包尾与指令合法性；不合法则整帧丢弃，从下一字节重新同步
- **非法帧（包头/包尾不对、未知指令、参数越界）一律静默丢弃，不应答**，上位机以超时判定（见 §7）

## 4. 指令集

### 4.1 0x00 握手（版本查询 / 状态查询）

```
→ A5 00 00 5A                        （数据字节固件忽略，恒发 0x00）
← A5 00 <fw> <proto> <ch> <sw> 5A
```

- `<fw>`：固件版本，单字节；v1 固件填 `0x00`，上位机不解析语义，仅透传显示
- `<proto>`：本协议版本，恒为 `0x01`
- `<ch>`：通道数，恒为 `0x07`
- `<sw>`：当前 7 通道电源状态位掩码，bit0~bit6 对应通道 1~7（1 = 开，0 = 关），bit7 恒 0

**识别判据**（打开串口时确认对端是 hub；串口较多时逐口扫描探测）：应答为 7 字节定长帧，且指令 = `0x00`、`proto` = `0x01`、`ch` = `0x07`、包尾 = `0x5A`。`<fw>` 与 `<sw>` 取值不参与判据。任一条不满足即判定非 hub。

握手应答顺带带回通道状态，上位机连接成功瞬间即可同步 UI，无需再补一轮查询。

0x00 可在会话中**随时重复发送**：hub 无主动上报能力，上位机**周期发送 0x00 即为状态轮询**（建议 3 秒），用于感知手动控制等带外通道变化；上位机应把每次应答的 `<sw>` 视作当前真实状态覆盖本地视图。

### 4.2 0x01 通道设置

```
→ A5 01 <data> 5A
← A5 01 <sw> 00 00 00 5A
```

数据字节：bit4 = 0 关 / 1 开，低 4 位 = **通道索引**（0 基：`0` = 通道 1，`6` = 通道 7），bit5~bit7 必须为 0。

- 例：开通道 1 = `0x10`；开通道 7 = `0x16`；关通道 7 = `0x06`
- 索引 ≥ 7 或 bit5~bit7 置位的取值非法，按静默丢弃处理
- ⚠ **本指令用 0 基索引，而 0x02 读电流用 1 基通道号（1~7）——两者基准不同**（历史原因，见 ADR-0006），实现与联调时务必区分

应答数据首字节 `<sw>` 为**动作执行后**的 7 通道状态掩码（编码同 §4.1），其余 3 字节为 `0x00`。示例（设置通道 1 关、其余本就开）：`A5 01 7E 00 00 00 5A`。

hub 通道状态可被手动控制改变：上位机以设置应答 + **周期 0x00 状态查询（§4.1，建议 3 秒）** 维护状态视图，确保感知带外变化。

### 4.3 0x02 读取通道电流

```
→ A5 02 <ch> 5A                      （<ch> = 通道号 0x01~0x07，1 基——⚠ 与 0x01 的 0 基索引不同！）
← A5 F<ch> <float32 LE> 5A           （应答指令 = 0xF0 | 通道号）
```

- 应答数据 4 字节 = IEEE 754 单精度浮点，小端，**单位 mA**
- 通道关闭时电流恒为 `0.0`
- 采样窗口由固件自定（建议每通道平均值取 ≥ 100 ms）
- 应答指令借用通道号表达（通道 1~7 → `0xF1`~`0xF7`），因 4 字节数据已全部被浮点占用

完整示例——读通道 3，电流 1024.0474 mA：float `0x44800184` 小端拆为 `84 01 80 44`，完整帧 `A5 F3 84 01 80 44 5A`。

## 5. 数据编码

| 量   | 编码                     | 单位 | 说明                                            |
| ---- | ------------------------ | ---- | ----------------------------------------------- |
| 电流 | IEEE 754 float32，小端   | mA   | 1 A 附近分辨率约 0.0001 mA，远优于 0.1 mA       |
| 电压 | 不传输                   | —    | 上位机恒按 5.000 V 假定                         |
| 功率 | 不传输                   | —    | 上位机计算：P(W) = 5.000 × I(mA) / 1000         |

## 6. 错误处理

无错误应答帧。非法输入（包头/包尾不对、未知指令、通道号越界、参数格式非法）hub 一律静默丢弃；上位机等待应答超时（见 §7）即按失败处理，必要时重试。

## 7. 时序约束

- 应答超时：200 ms 未收到完整合法帧视为超时，可重试
- 轮询节奏由上位机自定：电流轮询（默认 500 ms，7 × `0x02`，约 77 字节）；**状态轮询（建议 3 000 ms，1 × `0x00`）** 用于感知手动变化，两者互相独立
- hub 无发送缓冲：收到完整合法帧立即应答

## 8. 串口发现

1. 枚举系统全部串口（排除蓝牙虚拟口），按 CH340 控制口魔术字（§9）过滤，只展示 hub 控制串口
2. 过滤无命中时回退展示全部串口，由用户人工选择
3. 发 `0x00` 握手，按 §4.1 识别判据判定
4. 判定通过即认作 hub；超时或判据不符即关闭并探测下一个

hub 主控 USB VID/PID 魔术字是设备树定位的首选锚点（集中于 `src-tauri/src/magic.rs`），未配置时退化为上述全口扫描。

## 9. 魔术字（实物实测值）

| 项                   | 当前值          | 说明                                                         |
| -------------------- | --------------- | ------------------------------------------------------------ |
| hub 主控 USB VID/PID | `0x0451/0x8142` | 设备树定位 hub 的首选锚点；`0x0000` = 未配置，退化用全口扫描。实测 TI TUSB8041 两片级联组成 1 转 7（4+4 口，级联占 1 口），定位取最上游一片 |
| 控制串口 CH340 VID/PID | `0x1A86/0x7523` | 串口列表过滤锚点：只展示 CH340 串口，无命中回退展示全部。CH340 系列出厂固定描述符 |

## 10. 验收矩阵（联调回归清单）

任何一侧改动后按此逐条回归（2026-10-14 通道偏移问题的永久防线）：

1. 从全关起逐一开通道 1→7：每次**仅**物理口 N 亮，掩码 = 已开通道 `bit(N-1)` 之或
2. 逐一关 7→1：每次仅物理口 N 灭
3. 全开掩码 = `0x7F`；全关 = `0x00`；bit7 恒 0
4. 重新握手：握手掩码 = 当前实际状态
5. 通道基准核对：通道 N 接负载，`0x02` 读通道 N 电流随负载变化（N 为 1 基通道号）
6. 手动改变通道状态后，上位机在一个状态轮询周期（≤3 秒）内同步 UI
