# power-hub 串口协议规范 v1

> 固件与上位机的共同契约。本文档是协议的唯一权威来源；任何改动必须先改这里。
> 相关决策见 [ADR-0001](./adr/0001-文本行协议与纯被动应答.md)。

## 1. 物理层

- UART：115200 bps，8 数据位，无校验，1 停止位（8N1）
- 编码：ASCII 文本行
- 行尾：`\r\n`（hub 发送必须带 CRLF；解析端应容忍裸 `\n`）
- 最大行长：128 字节，超长视为非法行丢弃

## 2. 方向模型

严格一问一答（主从式）：

- 所有通信由上位机发起
- hub 收到一条合法命令后应答一行
- hub **永不主动发送**任何数据（无上电提示、无周期上报）
- hub 上电后处于待命状态，7 通道默认全部开启

## 3. 帧格式与校验

每行格式：`<payload>*<HH>`

- `<HH>`：payload 全部字节（不含 `*` 及其之后）逐字节异或（XOR）的两位大写十六进制
- 校验失败的行**静默丢弃**，不应答
- 空行忽略

示例：`PING` 的 payload 字节 `50 49 4E 47` 异或得 `10`，完整行为 `PING*10\r\n`。

## 4. 数字编码

| 量     | 编码       | 单位   | 示例             |
| ------ | ---------- | ------ | ---------------- |
| 电压   | 十进制整数 | mV     | `5023` = 5.023 V |
| 电流   | 十进制整数 | 0.1 mA | `8421` = 842.1 mA |
| 功率   | 不传输     | —      | 上位机按 mV × 0.1 mA 计算 |

整数编码精确承载 0.1 mA 分辨率，不使用浮点文本。

## 5. 命令集

### 5.1 PING —— 探活

```
→ PING*10
← PONG*16
```

### 5.2 VER? —— 查询版本与通道数

```
→ VER?*7E
← VER,<fw>,<proto>,<ch>
```

- `<fw>`：固件版本，如 `1.0.0`
- `<proto>`：本协议版本，恒为 `1`
- `<ch>`：通道数，恒为 `7`

### 5.3 PWR? —— 查询全部通道状态（轮询主命令）

```
→ PWR?*6A
← PWR,<sw1>,<mv1>,<c1>,<sw2>,<mv2>,<c2>,…,<sw7>,<mv7>,<c7>
```

- 共 21 个数据字段，通道按 1→7 顺序排列
- `<swN>`：通道 N 开关态，`1` = 开，`0` = 关
- `<mvN>`：通道 N 电压（mV 整数）；通道关闭时读数可为 `0`
- `<cN>`：通道 N 电流（0.1 mA 整数）；通道关闭时恒为 `0`
- 采样窗口由固件自定（建议每通道平均值取 ≥ 100 ms）

### 5.4 SW,n,ON|OFF —— 通道电源控制

```
→ SW,3,OFF*78
← OK*04
```

- `n`：通道号 1~7
- `OK` 表示动作已执行；开关切换的电气稳定时间由固件保证

## 6. 错误应答

无法解析或执行的命令应答：

```
← ERR,<code>,<msg>
```

| code | 含义                       |
| ---- | -------------------------- |
| 1    | 未知命令                   |
| 2    | 参数错误（格式/取值非法）  |
| 3    | 通道号越界（不在 1~7）     |
| 4    | 内部错误                   |

`<msg>` 为简短 ASCII 描述，不含逗号。

## 7. 时序约束

- 上位机应答超时：200 ms 未收到完整行视为超时，可重试
- 轮询节奏由上位机自定（默认 500 ms）
- hub 无发送缓冲：收到完整合法行立即应答

## 8. 待定项（魔术字）

以下硬件标识拿到实物后更新（上位机代码集中于 `src-tauri/src/magic.rs`）：

| 项                 | 当前值         | 说明                                                                 |
| ------------------ | -------------- | -------------------------------------------------------------------- |
| hub 主控 USB VID/PID | `0x0000/0x0000` | 设备树定位 hub 的首选锚点；`0x0000` = 未配置，退化用"下游口数 = 7"特征匹配 |
| 串口芯片 VID/PID   | 不依赖         | 串口发现采用"扫描全部串口 → 逐个 PING 探活"方案                       |
