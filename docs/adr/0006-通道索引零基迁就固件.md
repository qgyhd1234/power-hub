# 0x01 通道数据采用 0 基索引（迁就既有固件）

> Status: accepted（2026-10-14，首次实机联调）

实机联调发现：上位机开通道 N 实际点亮物理口 N+1、应答掩码整体 +1。根因是契约错位而非固件 bug——上位机按文档发送 1 基通道号（1~7），固件把该字节当作 0 基通道索引（0~6）解释，索引与掩码、GPIO 全部自洽。硬件侧决定不改代码，故文档与上位机迁就固件：0x01 的低 4 位重定义为 **0 基通道索引**（0=通道1，6=通道7，例：开通道1=`0x10`）。掩码维持原文档约定（bit0~bit6=通道1~7）不变。

## Considered Options

- **固件改 `1<<(ch-1)` 一行对齐文档**：修复成本最低的方案，曾被推荐；硬件侧决定不改代码后被否。
- **掩码也翻成 1 基（bitN=通道N）**：日志一度支持此假设，但与"0x02 读电流工作正常"矛盾且会让通道 7 触发上位机 bit7 拒收；已排除——固件掩码本来就是 0 基，错位只在 0x01 的请求方向。

## Consequences

- 同一协议内 0x01（0 基索引）与 0x02（1 基通道号）**通道基准不同**，实现与联调极易踩坑——规范 §4.2/§4.3 已用显著警告标注，验收矩阵附录（规范 §10）兜底。
- proto 字节仍为 `1`（固件硬编码），文档以 v2.1 变更记录区分。
- 领域词汇新增"通道索引"（GLOSSARY）：通道号 1 基是领域概念，索引是线上字节，两者在代码中不得混用。
