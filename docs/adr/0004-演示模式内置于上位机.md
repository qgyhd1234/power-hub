# 演示模式内置于上位机，而非虚拟串口对

无硬件时需要体验上位机。决定在上位机内实现 mock transport（演示模式）：协议层复用 `power-hub-protocol`，遥测由模拟器生成（电流噪声/漂移、虚拟设备插拔、SW 命令即时生效），从连接面板一键进入；不做 com0com 虚拟串口对方案。

## Considered Options

- **com0com 虚拟串口对 + Python 应答器**：完全走真实串口字节读写路径，但需要安装内核驱动（管理员权限、签名变数），且模拟不出设备插拔。
- **仅静态遥测**：无法展示插拔与曲线活力，体验价值低。

## Consequences

- 串口字节读写循环（`SerialSession` 的 open/read/write）在演示模式下不被覆盖，仍需实机联调——该路径本来就无法离线验证。
- 演示模式下本地 API 与 AI 技能拿到的是模拟数据（端口名显示"演示模式"），可顺带体验技能全流程；但不得将演示数据误当实测结果。
- 将硬件到手后如需离线联调真实串口路径，可再补 com0com 方案，两者不冲突。
