# 二进制帧协议取代文本行协议

> Status: 取代 [ADR-0001](./0001-文本行协议与纯被动应答.md)（其帧格式与编码部分被取代；纯被动应答与轮询模型继续有效）

固件侧按既定设计以定长二进制帧实现（原 `docs/二进制协议.txt` 草稿），且扫描识别（打开串口确认对端是 hub）天然适合"定长帧 + 固定字段判据"。决定：串口协议改为二进制帧——上位机→hub 4 字节（`0xA5` + 指令 + 1B 数据 + `0x5A`），hub→上位机 7 字节（`0xA5` + 指令 + 4B 数据 + `0x5A`）；指令 `0x00` 握手 / `0x01` 通道设置 / `0x02` 读电流；电流以 IEEE 754 float32 小端上报，单位 mA；帧不加校验字段，非法帧静默丢弃；hub 不传电压，上位机恒按 5 V 计算功率。全文见 `docs/protocol.md`。

## Considered Options

- **保留文本行协议（ADR-0001）**：AI 可解析、人工调试友好，但固件按二进制草稿实现已成既定事实，同一条串口链路上双协议并存没有收益。
- **二进制帧加 XOR/CRC 校验**：更严谨，但 USB 串口链路误码率极低，短定长帧 + 包头包尾 + 指令白名单已够用；且加校验会改帧长，与固件既定帧尺寸冲突。将来确有需要时经握手 `proto` 字节升版本再加。
- **握手应答带固定魔术字节加强识别**：零成本但非必需——判据已含"7 字节定长 + 指令 + proto=01 + ch=07 + 包尾"，误识别概率趋近于零，最终保留字节位用于通道状态掩码。

## Consequences

- 上位机协议层（串口解析、演示模式虚拟 hub、AI 技能直连串口路径）需按新帧格式重写对接；0.1 mA 整数编码、ERR 错误帧机制、`PING`/`PONG` 命令全部作废。
- 无校验意味着帧完整性完全依赖包头/包尾/定长/指令合法性过滤；若实机联调发现误码问题，升级路径是 `proto=2` 加校验，属破坏性变更。
- "电压恒 5 V"写入领域模型：hub 无电压遥测，功率永远是上位机计算值，显示精度受电流精度约束。
